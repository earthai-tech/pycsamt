# K2 — Stratagem (Geometrics/EMI) AMT field line

A real audio-magnetotelluric field survey collected with Stratagem hardware,
line "2HX" (site name **K2**), used as the bundled example/test dataset for
`pycsamt.stratagem`. 87 stations, nominal 20 m point spacing along a single
centerline (per the field report), acquired 2023-09-18 to 2023-09-21.

## What's here

| Path | Tracked | Contents |
|------|:-------:|----------|
| `k2-edi/` | yes, all 87 | WinGLink-exported EDI files (`Z2HX001.edi` … `Z2HX087.edi`). Coordinates are **not yet injected** — `LAT`/`LONG` are WinGLink placeholders (`0:00:00.00`). |
| `k2-HX/` | partial | Raw Stratagem hardware files. Only `X2HX.*`, `Z2HX.*` (19-column ASCII, ~6.6 MB total) and calibration/sensor files (`SENSORS.TBL`, `@`, `@S`, `AFEV3.*`, `BE26V2.*`, `S746_HX.*`, `S747_HY.*`) are tracked. |
| `k2-gps.xls` | yes | Raw GPS coordinate export, as delivered. |
| `k2-gps-ref.csv` | yes | Working coordinate table derived from `k2-gps.xls` (`lon`/`lat`/`elev`/`step`/`Site` columns — despite the header, `lon` holds the larger-magnitude Gauss-Kruger-style northing and `lat` the easting; see caveats below). 80 rows, **not** aligned 1:1 with the 87 stations. |
| `k2-field-report.docx` | yes | Daily field log (Chinese): date, weather, file number, chainage, terrain/interference notes per station. |
| `build_gps_aligned.py` | yes | Reconciles `k2-gps-ref.csv` against `k2-field-report.docx` into one coordinate row per station (see below). Re-run with `python data/stratagem/K2/build_gps_aligned.py`. |
| `k2-gps-aligned.csv` | yes | **Generated** by `build_gps_aligned.py`. 87 rows, one per `station_num` (1..87), ready to feed `CoordinateInjector`. |
| `k2-corrected-sample/` | yes, 5 files | A curated sample of the full pipeline's `export()` output (coordinates injected, static-shift corrected, frequency-filtered, denoised) — not the full 86-station batch, just enough to show real corrected output without bundling it twice. Original filenames (`Z2HXNNN.edi`). See below for which stations and why. |
| `k2-renamed-sample/` | yes, 5 files | The same 5 stations after `rename(basename="T2.")` — sequential `T2.0NN.edi` naming, `DATAID`/`SECTID` updated to match. ## About the corrected/renamed samples

`k2-corrected-sample/` and `k2-renamed-sample/` hold the same 5 stations,
picked to span the interesting cases the user guide (particularly
`docs/source/user_guide/stratagem/tutorial.rst`) walks through:

| Station | Renamed as | Why it's included |
|---------|:----------:|--------------------|
| `Z2HX002` | `T2.000` | First surviving station (station 1 is the dropped calibration shot). |
| `Z2HX040` | `T2.038` | An ordinary mid-line station — small static-shift correction. |
| `Z2HX058` | `T2.056` | Inside the low-hardware-coverage run (stations 56-61). |
| `Z2HX061` | `T2.059` | The static-shift outlier — `fac_z≈93` from a single spatial neighbour. |
| `Z2HX087` | `T2.085` | Last station, the extrapolated/check-point-duplicate endpoint. |

These are real `export()`/`rename()` output, not fabricated — generated by
running the full `StratagemSurvey` pipeline shown in the Usage section
below and copying just these 5 files out of the resulting 86-file
directories. Running that example yourself reproduces `k2_corrected/` and
`k2_renamed/` at the repo root; both are git-ignored there (see
`.gitignore`) since they're regenerable pipeline output, not source data —
only this small bundled sample is tracked.

## What's excluded

`k2-HX/Y2HX.*` (87 files, ~127 MB) are **not tracked**. Unlike `X2HX.*` and
`Z2HX.*`, they are raw binary time-series captures, not the 19-column ASCII
format `pycsamt.stratagem.io.StratagemRawReader` parses — passing
`component='Y'` or `component='ALL'` against this dataset today will not
produce meaningful masks. They remain usable locally (untouched by git) if
you have the original delivery; only the git exception was left out.

## Data-quality issues found in the raw delivery (and how `k2-gps-aligned.csv` fixes them)

`CoordinateInjector.fit()` requires exactly one coordinate row per EDI
station. `k2-gps-ref.csv` alone can't satisfy that — cross-referencing it
against `k2-field-report.docx` (via `build_gps_aligned.py`) surfaced four
real problems, none of which `gis_correct.py` handles automatically today:

- **Station count mismatch (87 vs. 80 rows)**. `2HX.01` is a
  calibration/"parallel test" shot at chainage 1 m (not a real profile
  position — excluded via `use_for_survey=False`), and `2HX.043`,
  `2HX.069`, `2HX.075`, `2HX.087` are "检查点" (check points) — QC repeats
  measured at the same physical location as the immediately preceding
  station (`source=checkpoint_dup`, coordinates copied from that station).
  A further physical point at chainage 560 m was GPS-shot but the CSAMT
  instrument never recorded a file there ("公路中间车很多测不了" — too
  much road traffic) — that orphan GPS row is simply unused.
- **Column shift**: in `k2-gps-ref.csv`, the `station` column's numeric
  suffix equals the *next* row's `step` value (off by one row) — `step` is
  the trustworthy per-row chainage; `station` should not be used directly.
- **Bad endpoint shot**: the last GPS row (`Site=K79`, `step=1640.4`) sits
  ~1640 m from the second-to-last row instead of the ~20 m design spacing,
  and its coordinates land on the profile's *start*, not its end — almost
  certainly a mislabeled re-shot near the origin. It's dropped, and the
  true endpoint (chainage 1640 m, stations 86/87) is instead extrapolated
  from a linear fit through the last 5 trusted points
  (`source=extrapolated`).
- **3 further gaps** (~1080, ~1260, ~1300 m) were never GPS-shot at all and
  are filled by linear interpolation between chainage-adjacent neighbours
  (`source=interpolated`).
- **Irregular spacing**: even the trusted rows drift ~19.7–20.7 m per
  interval instead of landing on exact 20 m multiples — expected GPS
  jitter around the nominal design grid ("点距20m" per the field report),
  not something `k2-gps-aligned.csv` attempts to snap to a perfect grid.

## Usage

```python
from pycsamt.stratagem import EDIBatch, StratagemRawReader

batch = EDIBatch("data/stratagem/K2/k2-edi").fit()
rdr = StratagemRawReader("data/stratagem/K2/k2-HX", component="X").fit()
```

`k2-gps-aligned.csv` has 87 rows (one per raw/EDI station, including the
station-1 test shot); `CoordinateInjector` needs exactly one row per EDI it
receives, so filter out `use_for_survey=False` rows first, matching the
dropped EDI station one-for-one. `easting_col`/`northing_col` must be given
explicitly — the table has more numeric columns (`station_num`,
`chainage_design_m`) than just the coordinate pair, and auto-detection
raises rather than guessing in that case (see `pycsamt.stratagem.gis_correct`).

The full pipeline, via `StratagemSurvey` (`drop_stations` takes 0-based
`EDIBatch` indices):

```python
import pandas as pd
from pycsamt.stratagem import StratagemSurvey

coords = pd.read_csv("data/stratagem/K2/k2-gps-aligned.csv")
coords[coords["use_for_survey"]].to_csv("k2_coords_for_injection.csv", index=False)

sv = (
    StratagemSurvey(
        edi_dir="data/stratagem/K2/k2-edi",
        coord_file="k2_coords_for_injection.csv",
        raw_dir="data/stratagem/K2/k2-HX",
        epsg=32649,           # UTM Zone 49N WGS84 — see below
        order="forward",
        drop_stations=[0],    # station 1 = calibration/test shot
        easting_col="easting",
        northing_col="northing",
        elev_col="elev",
        station_col="edi_file",
    )
    .fit()
    .run_qc()
    .remove_static_shift()
    .drop_frequencies(fmin=10.0, fmax=10000.0)
    .remove_noises()
    .export("k2_corrected")
)
print(sv.summary())
```

`epsg=32649` (UTM Zone 49N WGS84) is an assumption, not confirmed metadata —
it was chosen because it's `survey.py`'s documented default for "the
standard south-China survey area" and produces plausible results (~25.77°N,
109.63°E, Guangxi; elevations 200–350 m match the hillside terrain
described in the field report). Verify against your own project records
before treating the injected coordinates as final.
